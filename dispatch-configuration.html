Use Case A · FieldJetX · one table, one row per on-call region

Author Saravana Rajan Updated 11 Aug 2026 Supersedes the four-table draft of 6 Aug Applied local SQL only DEV / QA / STG pending DBA

1Schema diagram

One table, dbo.DispatchAutoConfig, one row per on-call region. The only relationship is a foreign key to the existing dbo.OnCallRegion, so loading a region's settings is a single row with no joins.

OnCallRegionId is also unique, which is what states “one configuration per region”. Emergency has no weight columns because it is locked to speed-based ranking.

2Columns

19 columns, and no DEFAULT constraints anywhere — every value is written by the service, so a default has one home rather than two that can disagree.

CHECK constraints are sanity rails only — strategy is one of the three codes, weights 0-100 and summing to 100, escalation 0-1440, offer timing 0-600, radius 1-500. The real limits are enforced in the service layer, so changing a slider range needs no DBA.

3The table in the database

dbo.DispatchAutoConfig in FieldJetXDev, with one configured region (Albuquerque, NM). Scrolled across in three parts because the row is 19 columns wide.

Region-wide settings and the start of Emergency: offer timing 30s, radius 40mi, Emergency on Speed.

Emergency escalates after 10 minutes; High is Familiarity at 0 speed / 100 familiarity.

High escalates after 20 minutes; Normal is Combined at 60 / 40 and escalates after 30.
